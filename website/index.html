NikoDesk design notes
Chapter 02 · The connection

A connection that
only concerns you.

Most remote desktops ask you to keep your device list, connection history and even your screen on someone else's servers. NikoDesk chooses the opposite: registration, discovery and relay all run on your own machines.

Solid: P2P direct (preferred) · Dashed: your relay (fallback)

I.

Registration you own

Your device list, online status and key exchange live only on your server. No accounts, no cloud sync, and no "platform" that can see what devices you have.

II.

Direct first

Sessions try NAT traversal first, so both ends talk directly. When the network does not allow it, traffic falls back to your own relay. You never choose between speed and reachability.

III.

Never calls out

Without private-server settings, the client connects to no public rendezvous server. That is not a promise — it is behaviour written into the code.

IV.

Leave anytime

The server side is the open-source RustDesk Server OSS, with no data locked into any format. Self-host today, migrate tomorrow — the choice stays yours.

Chapter 03 · Trust

Trust, where you can see it.

A sense of safety comes from mechanisms, not promises. NikoDesk keeps every boundary in plain sight.

/ 01

Choose who connects

Manage passwords and access rules on the remote computer. Grant viewing, input and file permissions separately, and end a session at any time.

/ 02

Permissions stay visible

Screen capture, input, camera and microphone follow system permissions. Allow access when needed and revoke it afterwards.

/ 03

Open for inspection

Built on the native RustDesk core under AGPL-3.0. Source code, build instructions and release notes are available on GitHub.

Chapter 04 · Get started

Two processes are all
the server you need.

1

Start rendezvous and relay

hbbs handles device registration and discovery, hbbr handles relaying. Two Docker commands are enough, or reuse an existing RustDesk Server OSS setup. See the self-hosting guide.

2

Set up both devices

Enter the same server address and public key on both devices. Allow screen capture and input access as needed.

3

Make your connection

Enter the remote device ID and access password. Save frequently used computers locally for next time.

your-server — sh
# A machine with a public address, two commands
$ docker run -d --name hbbs --net=host \
    rustdesk/rustdesk-server-oss hbbs -r relay.yourdomain.com
$ docker run -d --name hbbr --net=host \
    rustdesk/rustdesk-server-oss hbbr

# Fill the server public key into both clients
$ cat ./id_ed25519.pub

Chapter 06 · FAQ

Before you begin,
let's be clear.

We don't hide limitations. Four things people ask most about the current state of NikoDesk.

Do I need my own server?+
Yes: an accessible RustDesk Server OSS instance, including one you already run. NikoDesk does not connect to public rendezvous servers when private-server settings are absent.
Do downloaded updates install automatically?+
Updates currently require manual installation. Follow the installation steps after downloading: quit the old version, replace the app and reopen it. See the release page for details and signing information.
Can I control an Android phone remotely?+
The Android app is a controller for your Windows or Mac computer. It does not expose the phone for remote control.
How is NikoDesk related to RustDesk?+
NikoDesk is an independent open-source project built on the native RustDesk core under AGPL-3.0. It is not affiliated with or endorsed by RustDesk.
