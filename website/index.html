It never phones home

Every remote desktop needs a rendezvous server (hbbs) where devices register, and a relay (hbbr) for traffic when a direct link is not possible. Public tools run both for someone else's benefit. NikoDesk runs both for you.

Sessions negotiate through your server, punch a direct hole when they can, and fall back to your relay when they cannot. And the policy is not a promise in a policy document:

# the private-server rule is compiled in, not a setting
$ cargo build --features flutter,hwcodec,nikodesk
# a NikoDesk build cannot register with public rendezvous

Security, in plain words

NikoDesk inherits end-to-end encrypted sessions from the RustDesk core and adds its own house rules.

Admission

Sessions require the remote password before connecting. Temporary and permanent passwords are managed on the controlled side.

Accepting a session grants keyboard, mouse, clipboard and file transfer, each revocable per session. Audio stays off until you say otherwise.

Network

Registration and relay traffic point at the server you configure. The private-server-only build cannot fall back to public rendezvous.

Traffic prefers direct peer-to-peer links; your relay only ever sees encrypted frames, and only when punching fails.

Supply chain

Artifacts come from public GitHub Actions runs, hashed in SHA256SUMS. The updater fails closed on any mismatch.

Update downloads accept HTTPS hosts from a fixed allowlist and re-validate after redirects.

Own the server in three commands

NikoDesk speaks the open RustDesk server protocol. If you already run hbbs and hbbr, point the client at them and you are done.

Run the pair

Two containers on any Docker host. Keep the data volume so your key pair survives updates.

docker run -d --name hbbs -v /data:/root \
  -p 21115:21115 -p 21116:21116 \
  -p 21116:21116/udp -p 21118:21118 \
  rustdesk/rustdesk-server hbbs

docker run -d --name hbbr -v /data:/root \
  -p 21117:21117 -p 21119:21119 \
  rustdesk/rustdesk-server hbbr

Expose and harden

Give the host a reachable name, forward the ports, copy the public key. A home line works with port forwarding or a WireGuard tunnel.

cat /data/id_ed25519.pub
# point DNS at the host
# keep tcp 21115-21119 open

Point the clients

The same three fields on every device you trust. The connection test in settings tells you at once whether registration succeeded.

ID server:  desk.example.com
Relay:      desk.example.com:21117
Key:        (id_ed25519.pub)

Questions people actually ask

Do I need a public IP?
The hbbs and hbbr ports must be reachable by both ends. A home connection works with port forwarding or by putting the pair behind a WireGuard or Tailscale tunnel. Sessions still try to connect peer-to-peer directly; the relay only carries traffic when punching fails.
How secure is it?
Sessions use the RustDesk core's end-to-end encryption. NikoDesk adds a hard rule on top: the controller must supply the remote password before a session is ever dispatched, permissions are granted per session, and the updater refuses artifacts whose SHA256 sum does not match. You remain responsible for keeping the server key safe.
What is the relationship to RustDesk?
NikoDesk is an independent downstream product built on the RustDesk 1.5.0-pre core and UI, licensed under AGPL-3.0 like the upstream. Source code, build scripts and CI are public, so you can reproduce every release artifact yourself.
What can the Android build do?
It is verified as a controller: full remote control and file transfer toward your desktops. Acting as the controlled side works through the upstream core but has not been a verification focus, so treat it as experimental.
