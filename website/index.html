Why self-hosted

The signal path decides who can watch

Deploy

Fifteen minutes to your own server

Any x86_64/arm box that runs Docker works — a NAS at home is the usual choice.

# docker-compose.yml — rendezvous (hbbs) + relay (hbbr)
services:
  hbbs:
    image: rustdesk/rustdesk-server:latest
    command: hbbs
    volumes: [ "./data:/root" ]
    ports:
      - "21115:21115"
      - "21116:21116"
      - "21116:21116/udp"
      - "21118:21118"
  hbbr:
    image: rustdesk/rustdesk-server:latest
    command: hbbr
    volumes: [ "./data:/root" ]
    ports:
      - "21117:21117"
      - "21119:21119"
1

Start the server

docker compose up -d. The keypair appears in ./data — keep id_ed25519 private, you'll paste the .pub into clients.

2

Point NikoDesk at it

Settings → Private server: ID server, relay, public key. NikoDesk validates all three together and won't fall back to anything else if they're wrong.

3

Connect with a password

Controllers can be any RustDesk client. Enter the device ID and its password — NikoDesk refuses to dispatch a session on an ID alone.

Features

Everything a daily driver needs

Real RustDesk core, unmodified behavior

Remote control, file transfer, clipboard sync, multi-display switching, hardware-encoded VP8/VP9/AV1/H.264/HEVC — the same battle-tested engine, re-skinned as a product.

Device workspace with live presence

Cards with aliases, groups, favorites and rendezvous-backed online status. When presence can't be proven, NikoDesk says unknown instead of guessing.

Session history that tells the truth

Local, capped at 200, corruption-tolerant. It records what you initiated and never claims the far side accepted — one click reconnects with the same parameters.

Receiver-side consent, per session

Incoming sessions surface a confirmation card with live permission toggles — keyboard/mouse, clipboard, file, audio — granted on accept and revocable mid-session.

Dual themes, one binary

A light workspace with soft gradient glass and a deep-navy night console. System-following with a manual override, applied across home, settings and the confirmation window.

Coexists with stock RustDesk

Isolated bundle id, config directory, IPC namespace and device identity. Install both, run both — they never read or write each other's state.

Deliberately not included in v1.0.0: terminal, TCP/UDP tunneling, camera viewing, remote restart, privacy mode and local-input blocking — removed at compile time, not hidden in settings.

Security model

Three locks between the world and your desktop

1

Network lock

Private-server-only is enforced in the connection layer: an unconfigured or malformed server yields no connection attempt at all, and rustdesk.com endpoints are rejected by the config validator itself.

2

Session lock

Controllers must present the remote password before any handshake leaves the machine. On the receiving side every session re-confirms permissions, and the private key never leaves the controlled device.

3

Update lock

The updater talks only to api.github.com / release hosts over HTTPS (allowlisted, redirects re-checked), and installs nothing unless the downloaded bundle matches the release's published SHA256. Fail-closed.

Release builds are locally signed (no Apple Developer ID / notarization). For organization-wide deployment, re-sign with your own certificate before distribution.

FAQ

Questions people actually ask

How is this different from just running RustDesk?

Stock RustDesk defaults to the vendor's public servers and allows passwordless confirmation flows. NikoDesk compiles the private-server policy into the client, gates controlling on passwords, ships a redesigned product UI, and adds verifiable updates. It stays wire-compatible: any RustDesk client can control a NikoDesk device and vice versa.

Do I have to run my own server?

Yes — that's the point. hbbs/hbbr run fine on a €4 VPS or any Docker-capable NAS. Without a server configured, NikoDesk simply won't connect anywhere.

Can NikoDesk and RustDesk coexist on one machine?

Yes. Separate bundle id (io.nikodesk.macos), separate config and IPC namespaces, separate device identities. Neither touches the other's files.

How do updates reach my machine?

Settings → Software update → Check for updates. macOS updates download, verify SHA256 against the release manifest, and swap the installed app automatically. Windows and Android get a download link for the same release.

What about ToDesk / TeamViewer features X/Y/Z?

v1.0.0 covers control, file transfer, clipboard, multi-display, session history and guided permissions. Features that require elevation or weaken isolation (privacy mode, remote restart, tunneling) are intentionally out. The roadmap lives in the repo issues.

Is the session really end-to-end encrypted?

Yes — same as upstream RustDesk: the peers exchange keys signed by the device identity, and relayed traffic is E2E encrypted; the hbbr relay sees ciphertext only.
