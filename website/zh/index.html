不向任何公共服务器报到的远程桌面

远程桌面离不开两个服务：注册服务器（hbbs）负责让设备互相找到对方，中继（hbbr）在无法直连时转发流量。

公共远控工具把这两个服务握在厂商手里。NikoDesk 让它们跑在你自己的机器上，NAS、VPS 或任何你能控制的主机都可以。会话经你的服务器协商，能打洞就点对点直连，打不通才走你的中继。

私服策略是编译进客户端的。NikoDesk 构建不会向公共注册服务器报到，实验客户端永远不可能泄漏到共享基础设施上。

为日常使用而做，不为演示而做

以下功能全部随 v1.0.0 交付。尚未验证的地方，界面会如实标注，而不是装作没有问题。

密码就是门禁

只输入 ID 永远不会发起连接。NikoDesk 只有在远程密码就位时才出手，一次手滑也不会敲响别人的机器。

一套界面，两种气质

夜间控制台与日光画布，跟随系统外观，设置里可手动切换。

在线状态真实可信

设备卡片每六秒向你的注册服务器查询一次，显示在线、离线或未知。未知就是未知，不含糊。

历史与录像

本地保存最近 200 次连接记录，一键复连；会话可以录像留档。

更新先验哈希

应用内即可检查更新。下载只走 GitHub Release 的 HTTPS 通道，SHA256 校验不过就拒绝安装。

安全边界，摊开来讲

NikoDesk 继承 RustDesk 内核的端到端加密会话，并加上自己的规矩。

准入

连接必须先过密码关。临时密码与永久密码都在受控端管理。

接受一次入站会话，等于授予键盘、鼠标、剪贴板与文件传输，逐会话可随时收回。音频默认关闭，需要时再打开。

网络

注册与中继流量只指向你配置的服务器。仅私服构建没有回落到公共注册服务器的选项。

流量优先点对点直连；只有打洞失败时，你的中继才经手加密数据帧。

供应链

发布产物由公开的 GitHub Actions 构建并写入 SHA256SUMS，更新器在任何不匹配时一律拒装。

更新下载只接受固定白名单里的 HTTPS 主机，重定向后重新校验。

三条命令，服务归你

NikoDesk 说的是开放的 RustDesk 服务端协议。如果你已经在跑 hbbs 和 hbbr，把客户端指过去就能用。

起服务

任意 Docker 主机上两个容器。保留数据卷，密钥对在升级后依然有效。

docker run -d --name hbbs -v /data:/root \
  -p 21115:21115 -p 21116:21116 \
  -p 21116:21116/udp -p 21118:21118 \
  rustdesk/rustdesk-server hbbs

docker run -d --name hbbr -v /data:/root \
  -p 21117:21117 -p 21119:21119 \
  rustdesk/rustdesk-server hbbr

通网络

给主机一个可访问的域名，放行端口，再从数据卷取出公钥。家庭宽带用端口映射或 WireGuard 隧道都可以。

cat /data/id_ed25519.pub
# DNS 指向主机
# 放行 tcp 21115-21119

填客户端

在每台信任的设备上填同样的三栏。设置页的连接测试会立刻告诉你注册是否成功。

ID 服务器:  desk.example.com
中继:      desk.example.com:21117
Key:      (id_ed25519.pub)

大家真正会问的问题

必须有公网 IP 吗？
hbbs 与 hbbr 的端口需要能被两端访问。家庭宽带做端口映射，或者把这对服务放进 WireGuard、Tailscale 隧道都可以。会话依然会优先尝试点对点直连，中继只在打洞失败时才参与。
安全性到底怎么样？
会话沿用 RustDesk 内核的端到端加密。NikoDesk 在其上加了一条硬规矩：控制端必须拿到远程密码才会派发会话；权限按会话授予、随时可收回；更新器对哈希不匹配的安装包一律拒装。服务器密钥的保管责任在你。
和 RustDesk 是什么关系？
NikoDesk 是基于 RustDesk 1.5.0-pre 内核与界面的独立下游产品，遵循与上游一致的 AGPL-3.0。源码、构建脚本与 CI 全部公开，每个发布产物你都可以自己复现。
Android 版能做什么？
已验证的定位是控制端：向你的桌面发起完整远控与文件传输。作为受控端的能力来自上游内核，但不是我们的验证重点，请按实验特性对待。
