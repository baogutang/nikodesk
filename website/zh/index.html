NikoDesk 的出发点
连接哲学

连接这件事，
只与你有关。

一般的服务会替你保管设备列表和连接记录，画面也要从别人的服务器走一遍。NikoDesk 反过来：注册、发现、中继，都跑在你自己的机器上。

实线：P2P 直连（优先） · 虚线：自有中继（兜底）

壹

注册自主

设备列表、在线状态和密钥，只存在你的服务器上。没有账号，也没有云端同步。

贰

直连优先

能打洞直连就直连，两端直接对话；实在不行，才走你自己的中继。

叁

永不外连

没配私服时，客户端不会去连任何公共注册服务器。这是代码里写死的行为，不是口头承诺。

肆

随时离开

服务端就是开源的 RustDesk Server OSS，没有私有格式。哪天不想用了，换掉就是。

信任边界

信任，建立在看得见的地方。

光说安全没有用，得能自己验证。下面三件事，现在就可以去查。

/ 01

你决定谁能连接

密码与接入策略由被控端管理。查看、操作和文件访问可以分别授权，会话也可以随时结束。

/ 02

权限清楚可见

屏幕录制、键鼠控制、相机和麦克风遵守系统权限。需要时授权，用完后可以撤回。

/ 03

实现公开可查

基于 RustDesk 原生内核，遵循 AGPL-3.0。源码、构建说明和版本变更都可在 GitHub 查看。

适合谁

它适合谁，
不适合谁。

先说清楚一件事：NikoDesk 需要一台你自己的服务器。这不是缺点，是它的前提。

它适合你，如果
  • 你有一台带公网地址的机器——云主机、NAS 或常开的电脑，或者愿意添置一台
  • 你已经在运行 RustDesk Server，想换一个更顺手的客户端
  • 你在意设备目录和连接记录存放在哪里
  • 你愿意用一次部署，换长期的自主与安静
暂时不适合，如果
  • 你希望注册一个账号，立刻连接任何电脑
  • 你不想接触服务器、Docker 与命令行
  • 你需要手机被控、网页端等尚未提供的能力

更像右边那栏？现在先别装，省得折腾。连接永不经过第三方的代价，就是服务器得自己出——这是当初就想清楚的取舍，不是以后会补的功能。

开始使用

两个进程，
就是完整的服务端。

1

启动注册与中继

hbbs 负责设备注册与发现，hbbr 负责中继。Docker 两行命令即可运行，也可复用已有的 RustDesk Server OSS。详见 自托管文档。

2

配置两端设备

在两端填写相同的私服地址与服务端公钥。按需要允许屏幕录制与键鼠控制。

3

建立你的连接

输入远端设备 ID 与访问密码，进入桌面。常用设备可保存在本地，方便下次使用。

your-server — sh
# 一台有公网地址的机器，两行命令
$ docker run -d --name hbbs --net=host \
    rustdesk/rustdesk-server-oss hbbs -r relay.yourdomain.com
$ docker run -d --name hbbr --net=host \
    rustdesk/rustdesk-server-oss hbbr

# 把公钥填进两端客户端

问答

上手之前，
把话说清楚。

有几个限制，先说在前面——也是被问得最多的。

需要自己的服务器吗？+
是的——这是唯一的前提。NikoDesk 不提供、也不连接任何公共注册服务器：开始连接前，你需要一台自己的服务器（复用已有的 RustDesk Server OSS，或按「开始使用」两行命令部署）。没有服务端，客户端不会替你连接任何人。
下载更新后会自动安装吗？+
目前需要手动安装。下载完成后，按应用中的安装提示退出旧版、替换应用并重新打开；具体步骤与签名说明见发布页。
Android 可以被远程控制吗？+
当前 Android 版只作为控制端，连接你的 Windows 或 Mac 电脑，不提供手机被控能力。
和 RustDesk 是什么关系？+
NikoDesk 是基于 RustDesk 原生内核的独立开源项目，遵循 AGPL-3.0，与 RustDesk 官方没有从属或背书关系。
